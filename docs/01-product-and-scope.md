## 2. 原作基準與資料界線

以五張圖片呈現的經典外觀為視覺基準。參考圖可能來自不同年代與改版，不能直接把全部版本內容混為同一個原版。

原作百科索引可確認四個職業類別：劍客、藥師、謀士、仙道；並包含神仙、戰寵、坐騎、裝備、任務、地圖、合成與轉生等內容入口。這只確認系統存在，不表示已取得每個項目的規則。[SRC-01，見來源表](02-reference-and-reconstruction.md)

完整內容盤點需為每個實體建立 `id / 類型 / 版本 / 來源 / 確認程度 / 美術狀態 / 程式狀態 / 測試證據`。目標版本未確定前，不宣稱「全部角色、全部地圖、百分之百原版數值」已納入。

預設採「截圖外觀優先的經典基準版」，先凍結一個可驗證的內容清單。後期版本另建內容包；要切換基準時保留差異清單。

## 3. 主要體驗

玩家建立角色，在城鎮接任務、出城探索、遭遇戰鬥；選擇角色與戰寵指令，獲得經驗和道具，回城更換實際可見的裝備，培養神仙、戰寵與坐騎，再與其他玩家組隊挑戰。

探索採點擊目的地尋路，虛擬搖桿為可選項。戰鬥採收集指令後依規則結算的回合制設計。隊伍容量、出手公式、神仙上場或變身方式、陣法加成、捕捉與掉落公式均需補證；開發用暫定值必須可替換。

## 5. 第一段可玩流程（M2）

這是重製計畫的功能切片，不是完整原版內容：

- 一座城鎮、一張野外地圖、一個戰鬥場景；三名具功能的 NPC。
- 一條 15–20 分鐘任務鏈，至少五個步驟：接取、探索、戰鬥、取得物品、交付。
- 一職業、六個具不同效果的技能、三種一般敵人、一種頭目、一隻可出戰戰寵。
- 一位神仙的規則與視覺樣本；若原作出戰方式仍未知，標記研究版並阻擋「原作一致」驗收。
- 至少十二個裝備／道具定義；可視裝備沿用 M1 已驗收資產，普通材料不需外觀資產。
- 經驗、任務、獎勵、背包、穿戴、角色動畫及存檔形成完整循環。

M3 將同一流程接上權威伺服器，先驗證兩名真實玩家，再測試五人隊伍。五人是容量假設，不是已證實的原作上限。

## 6. 完整版的定義

凍結的版本清單全部通過美術、玩法、資料、多人與真機驗收；未知項不得默認完成。機制可用測試數據先開發，對外必須註明測試值。原作資產若未提供可使用檔案，列入重建工作量與來源台帳；參考截圖不等於可直接使用的角色動畫素材。

決策順序：角色外觀與動作 → 手機操作 → 核心玩法 → 多人可靠性 → 內容量產。擴充內容不能用來掩蓋角色不像、人物消失或換裝失效等核心問題。
