## 3. 為什麼前幾次修正失敗

| 問題 | 已查到的原因 | 重建方式 |
| --- | --- | --- |
| 頭顯得更大 | 0.1.3 將身體高度乘 0.82、頭部乘 1.10；頭相對身體的縮放比變為 `1.10 / 0.82 ≈ 1.34` | 撤銷以獨立縮放修身形的做法，在同一完整人體上重建比例；冠飾另計 |

| 肩膀臃腫、手臂像外掛 | 胸甲素材已帶肩甲，手臂素材又帶一組；`drawArm` 以固定位置疊上去 | 肩甲只有一個歸屬，胸／肩／上臂接縫在來源工程檢查 |
| 手臂像木板旋轉 | 整條 arm 圖片只繞肩膀旋轉，沒有肘部與腕部獨立關節 | 完整的肩、上臂、肘、前臂、腕、手掌骨架，動作先於切圖完成 |
| 手腕和握武器不自然 | 手圖包含長護腕，手臂也有袖口；手和武器用固定偏移疊合 | 護腕只畫一次，建立手掌握點、武器握柄及不同武器的姿態族 |
| 轉向時身體不對 | 只有前／後頭部；背面軀幹仍用正面胸甲，再蓋裙片；其他方向縮窄或鏡像 | 同一來源角色渲染真正方向，持武器的左右方向不能直接鏡像 |
| 動作缺少重量 | 裙片擺動、靴子平移、人物上下浮動代替骨盆和步態 | 先做重心、腳底接地、膝肘彎曲，再加衣袖和髮尾次級動作 |
| 畫風偏離 | 生成規格強調細密金屬雕花、寫實材質和漂亮頭像；沒有先批准完整人物剪影 | 從遊戲實際尺寸的造型出發，降低紋理密度，明確區分布、皮、金屬 |
| 介面比人物搶眼 | 左側任務卡、中央大標題、底部大選單占據場景 | 縮減常駐資訊，重新安排可操作區域與人物站位 |

紅甲的額外量化證據：在一般斜向站姿、未計整體場景縮放時，胸甲來源 278×262 被畫成 `54×1.08` 與 `43×0.82`，其長寬比相對來源增為約 1.559 倍；手臂約 1.134 倍，手圖約 1.379 倍。這些是**圖片矩形的形變**，不是人體測量；已足以證明不同部件沒有保持一致形狀。

原先 03 文件其實已要求共用骨架、多方向素材與完整人物對照；實作卻改為獨立生成分件、手寫座標拼裝，沒有先完成那個品質關卡。問題包含規劃未落實與視覺驗收不足，不是改用網頁技術就必然做不到。此次以 R1 的來源工程、方向圖和實際尺寸畫面作為具體依據，不能再次只交計畫後直接量產零件。

因此，繼續把頭調小幾個像素、把脖子補色或把手移近，無法解決完整的人體結構。0.1.2 頸部遮擋修正僅處理局部，0.1.3 比例調整沒有通過使用者的視覺檢查。

## 4. 新的美術方向

| 面向 | 目標 | 現有資產的處理 |
| --- | --- | --- |
| 人物 | 帶立體明暗的經典 Q 版／半 Q 版遊戲角色；頭、胸、骨盆、四肢能連成自然的人體 | 重建整體角色；不沿用現有分件作最終人體 |
| 臉與頭髮 | 在小尺寸仍可辨認的臉形、瀏海、側髮與表情；頭部和身體同一美術語言 | 目前寫實娃娃臉降為舊稿；新臉以完整人物取景驗證 |
| 頭飾 | 保留參考中可辨認的輪廓與顏色，與自然頭部尺寸分開量測 | 頭飾不再帶動整顆頭或頸部高度 |
| 衣服 | 主要色塊清楚，腰帶、袖型、衣擺影響剪影；細節用在能看見的位置 | 重做紅甲、青袍、銀甲；不共用不相容肩甲 |
| 武器 | 劍、長柄、法杖各有長度、重心和握法 | 保留槽位與資料 ID，圖與姿態重新製作 |
| 光影 | 同一斜俯視相機、同一主光向、有限高光、乾淨接地影 | 現有怪物、寵物、背景稍後一起校色和對齊尺度 |
| 地景 | 低彩度、可讀的地面，角色與互動物清楚突出 | 首輪保留地圖，只作尺度對照；角色通過後再調地景細節密度 |
| 介面 | 參考圖的藍／綠面板與金橘邊線語彙，配合手機觸控 | 重新整理字級、邊框、間距與布局，不以桌面尺寸直接縮小 |

「有中國風」「有 Q 版頭」「有金屬材質」都不足以判定符合參考。每張提交需列出剪影、自然頭身比、肩臂、衣服、握法、相機與色彩的實際差異。

## 5. 基準人體與比例規格

先建立一名銀髮、紅色配件男性基準角色。REF-05 用於可見臉髮／配件／騎乘外觀，REF-01／02／03 用於站姿和遊戲尺寸；不把不同角色拼成「原版同一人」。不清楚的衣紋或背面明確標示重建假設。

1. **定義量測基準。** 自然頭高＝頭骨頂到下巴；身高＝頭骨頂到足底。髮束、角、冠、武器、名牌、影子均另記，不混入頭身比。若頭骨被遮擋，記錄估計範圍，不能填成精確原作值。
2. **起始草模。** 以約 4.25 個自然頭高製作第一名角色，4.0–4.5 僅作內部比較範圍，這是本次設計起點，並非已量得的參考數值。先檢查自然頭、肩寬、胸腔、腰、骨盆、腿長，再加髮冠和盔甲。不得將所有 NPC、怪物強制套成同一頭身比。
3. **先調人體，再穿衣服。** 肩膀到肘、肘到腕、腕到握點必須連續；沒有雙肩甲或雙護腕。衣服有厚度，但不得靠放大肩甲掩蓋缺少上臂。
4. **相機固定。** 試作斜俯視、近正交構圖；第一輪以 30–35° 俯角作測試範圍，和參考腳背／肩面可見程度比對後固定，不稱為原始引擎角度。所有衣服、武器與角色共享此設定。
5. **在實際尺寸看。** 以 844×390 CSS px 橫向舞台作首個基準，站立人物自然身高先試 88–100 CSS px，另附 1× 與 3× 檢視。這是新稿驗證尺寸；最終以場景、人寵比例與操作空間調整，不能拿螢幕截圖實體像素直接當 CSS px。
6. **同一比例跨場景。** 城鎮、戰鬥、換裝預覽、NPC 和頭像讀同一角色來源；可以改鏡頭與整體縮放，不得各自扭曲頭或胸。頭像只改取景，不另放大頭部。

首份基準稿要有無頭飾站姿、穿紅甲站姿、持劍姿勢、背面及場景 1× 對照。單張華麗立繪不算交付。

## 6. 資產與動畫製作路線

採用**完整角色來源 → 共用骨架與裝備 → 固定相機渲染 → 分層動畫圖集 → Canvas 播放**。這是重新落實 03 原先要求的製作路線，用於替換目前的拼貼實作；不是對原作內部技術的推斷，也不是已存在的能力宣告。

來源工程選可編輯、可綁骨的模型及材質；首選 Blender 離線製作。此次工作環境未找到 Blender 執行檔，現有 repo 也沒有這名角色的模型／骨架；在 R1 開始時先落實可用工具與來源工程，不能把這項依賴藏起來。AI 圖片可做完整造型設計參考，不能將一次生成的零件拼圖直接稱為生產圖集，更不能逐幀各自生成造成臉、手、武器跳變。

為降低換裝接縫，一套衣服中的軀幹、肩、袖、裙和腿部動作先在同一骨架中完成，再按需要輸出前／後切片；執行期不再用不同長寬比拼接和搖動整條手臂。角色外觀仍有獨立的衣甲、頭飾、髮型／髮色、武器與坐騎槽，不退回預製全身皮膚。

| 契約 | 最低要求 |
| --- | --- |
| 骨架 | 足底根節點、骨盆、脊椎、頸、頭，左右肩／肘／腕及髖／膝／踝 |
| 握法 | 劍以主手握點；長柄武器依動作增加副手約束；法杖有獨立施法姿態。副手不能穿桿 |
| 方向 | 同一模型的八方向投影；非對稱頭飾、衣服、左右手及武器不鏡像替代 |
| 動作 | 同一 action、phase 和事件時間；皮膚、衣服、武器及影子同步 |
| 圖層 | 方向／動作／幀決定前後切片和遮罩，不能永久固定「手永遠在胸前」 |
| 掛點 | foot、neck、wrist、grip、saddle 等由來源匯出，不用散落的手寫像素修正 |
| 防重複 | 肩甲、護腕、手掌只由一個部件提供；衣服遮住的身體用遮罩處理 |
| 缺件 | 新外觀整套載入後一次切換；失敗保留上一套完整外觀並可重試 |
| 可追溯 | rigVersion、assetVersion、來源檔、相機、材質、匯出設定、atlas hash 隨提交記錄 |

先交付八方向的待機、行走、劍攻擊，再補施法、防禦、受擊、倒地和勝利。03 中的幀數保留為候選，不把機械達到固定幀數當品質門檻；預備、命中、回收與循環接點必須完整。腳在接地段固定，身體有重心轉移；大衣袖和髮尾最後才加入。

記憶體按解碼後尺寸計算。首輪圖集頁上限先取 2048² RGBA，即約 16 MiB／頁；四頁約 64 MiB，尚未計背景、Canvas、瀏覽器及其他副本。這只是人物圖集初始預算，不是總記憶體實測。依方向／動作分包，先跑一服裝一武器的小樣，再以實際頁數決定完整方案；不預先烘焙所有混搭成全身動畫，也不載入所有造型所有方向。

## 7. 工程範圍

保留現有原生 ES Modules、Canvas、本機核心與存檔。風格問題不以更換 Vue、Phaser 或整個框架解決；先建立角色資產契約與統一播放端。以下是預計新增或拆分的檔案，**目前尚未實作**。

| 模組 | 責任 |
| --- | --- |
| `src/characters/manifest.mjs` | 角色、裝備相容性、動畫族與圖集索引 |
| `src/characters/renderer.mjs` | 共用時間、幀選取、足底對齊、切片排序、遮罩 |
| `src/characters/appearance.mjs` | 裝備外觀解析、載入完成後原子切換 |
| `tools/character-export/` | 來源模型、骨架與固定相機的匯出設定及可重現步驟 |

新 renderer 先在獨立角色驗證場跑，再替換 `drawHero`。先核對可用裝備 ID 與舊存檔映射，沿用 schema 1 的既有數值與進度；若資料格式真的需要改變，另加明確遷移和回復案例，不能因換美術而重置進度。

## 8. 手機畫面與操作重整

- 探索：左上保留緊湊頭像與 HP／MP；任務預設一行，可展開。場景名稱縮小，切圖短暫顯示。地圖靠角落並可收合；底部選單降低高度、靠邊配置。角色所在和行走區保持可見。
- 戰鬥：保留可辨識的斜向敵我站位、腳下圈和血條。選指令、選目標、確認的狀態繼續區分；實際按鈕配置以參考與手機可操作性一起核對，不能聲稱目前新增的確認流程就是原版行為。
- 觸控：按鈕目標先取至少 44×44 CSS px；人物碰觸範圍獨立於美術大小。角色變小也不能變得點不到；重疊目標仍可從列表選取。
- 鏡頭：人物不再因預留控制列而任意各自放大，先調世界鏡頭與站位。名稱、生命條及選取框從實際圖集 bounds 計算，取代固定假設高度。
- 驗證視窗：844×390、932×430、667×320，以及 1194×557 的內嵌視窗；均看完整介面、場景與人物，不能只交透明底角色大圖。超短視窗先收合資訊，不硬塞全部面板。

上述尺寸是設計起點，需在 Safari 分頁與 PWA 主畫面模式各自測試安全區、方向切換和點擊；離屏 Canvas 無法代替這項驗證。
